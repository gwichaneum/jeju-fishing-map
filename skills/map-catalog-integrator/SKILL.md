# 지도·도감 연결

## 작업 절차

1. 구현 전에 [integration-contract.md](references/integration-contract.md)를 읽고 실제 HTML·서버 허용 목록·라우팅을 확인한다. 문서 예시 주소가 현재 존재한다고 가정하지 않는다.
2. `spot-filters.js`의 실제 필터 값과 speciesCatalog를 읽어 speciesId→mapSpeciesKey 매핑을 확인한다. 표시 이름 문자열끼리 비교하지 않는다.
3. 도감→지도 이동과 유효 키 필터 적용을 구현한다. 파서와 필터 옵션 준비가 끝난 뒤 적용해 비동기 초기화 경쟁을 피한다.
4. null/미확인 키·관련 포인트 없음·잘못된 URL 입력을 명시적으로 처리한다. 지도 Popup은 기존 정보와 디자인을 보존하며 도감 버튼·링크·Chip·수집 상태를 추가하지 않는다.
5. 실제 라우트에 맞는 query parser·직접 접속·뒤로 가기와 공통 Segmented Navigation을 함께 완성한다. 모바일 focus·스크롤도 확인한다.
6. `npm test`와 tester의 정적 검사를 실행하고 검색·필터·Popup·즐겨찾기·현재 위치·화장실·날씨·물때·모바일을 회귀 확인한다.
7. `docs/SKILL_USAGE.md`에 실제 경로·매핑·명령·브라우저 결과·남은 한계를 기록한다. 실패한 이동을 완료로 기록하지 않는다.

## 입력과 출력 예

- 입력: “무늬오징어 도감에서 포인트 보기 연결”. 출력: 실제 도감 speciesId→`무늬오징어` 필터→표시 가능한 관련 마커, Back으로 이전 도감 복귀. Popup은 기존 정보 그대로 유지.
- 입력: 지도 키가 없는 쏨뱅이. 출력: 관련 포인트 미확인 안내와 일반 지도 이동. `우럭` 필터를 대신 적용하지 않는다.

## 예외와 검증

연결은 도감→지도 한 방향이다. 화면 간 일반 이동은 상단 Navigation을 사용한다. Popup→도감 이동은 정보량과 가독성을 고려해 제외하며 미완료 작업으로 남기지 않는다. 기존 도감 상세 query는 유지할 수 있지만 지도 Popup에서 생성하지 않는다.
어종 URL 파서가 없는 상태에서 예시 `index.html?species=...`를 활성화하지 않는다. 현재 구현 경로와 지원 query는 integration contract를 따른다.
도감 새 파일·이미지는 서버 allowlist에 정확한 경로만 등록한다. 프로젝트 전체 정적 공개로 404를 우회하지 않는다.
좌표 미확인 포인트는 검색에 남아도 이동·마커에서 제외한다. 메모/제보 매칭을 공개 확정 정보로 바꾸지 않는다.
오류·알 수 없는 ID에는 기본 화면/찾을 수 없음 안내를 제공하고 오류를 console에 방치하지 않는다.
정적 검사 실패는 수정 후 다시 실행하며, 브라우저 이동 검증을 정적 검사로 대체하지 않는다.
