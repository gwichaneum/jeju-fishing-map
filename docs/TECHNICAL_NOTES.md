## Run Locally

Use Node.js 22 or newer. Run `npm install` once, then `npm start` from the project
folder and open http://127.0.0.1:8080. No frontend build step is required.
MapLibre, OpenFreeMap and Open-Meteo need an internet connection, but no API key.
Official KHOA tides additionally require the ServiceKey configuration below.
Without that key, the rest of the app continues working.
`node serve.cjs` still starts the same Express server; `npm run dev` enables Node's watcher.

If port 8080 is already in use, PowerShell can run `$env:PORT = "8081"; npm start`
and open http://127.0.0.1:8081 instead.

PowerShell에서 `npm.ps1` 실행 정책 오류가 나면 `npm.cmd install`, `npm.cmd start`를 사용한다.
실행 정책 변경은 필요 없다. 서버 코드/제공 파일 목록 또는 `.env`를 바꾸면 서버를 재시작한다.
HTML/CSS/JS는 디스크에서 읽는다. 기존 서버가 이미 실행 중이면 같은 프로젝트 서버를 종료한 뒤 시작한다.

## 공식 물때 API 설정

1. [공공데이터포털의 해양수산부 국립해양조사원_조석예보(고, 저조)](https://www.data.go.kr/data/15156018/openapi.do)에서 활용신청한다.
2. 승인된 ServiceKey를 준비한다. 일반 인증키 **Decoding** 값을 권장한다.
3. 프로젝트 루트의 `.env`를 연다. 파일이 없으면 `.env.example`을 `.env`로 복사한다.
4. `DATA_GO_KR_SERVICE_KEY=발급받은키`로 설정한다. 실제 키는 로컬 `.env`에만 보관하고 `.env.example`에는 예시 값만 둔다.
5. `npm install`로 Express와 dotenv를 설치한다.
6. `npm start`로 실행한다. 키를 변경한 후에도 서버 재시작이 필요하다.

키는 대화, 스크린샷, frontend 파일 또는 Git에 넣지 않는다. `.env`와 `.env.*`는 Git에서
제외하며 `.env.example`만 예외로 공개한다. `node_modules/`도 제외한다.
서버는 프로젝트 `.env`에서 dotenv로 키를 읽으며, 브라우저에 키/상위 API URL/원본 오류를 반환하지 않는다.
Encoded 키도 서버가 한 번만 디코딩/인코딩하지만 Decoding 값을 사용하면 중복 인코딩을 피할 수 있다.

키가 없으면 시작 시 `DATA_GO_KR_SERVICE_KEY가 설정되지 않았습니다.`를 출력하고
`/api/tides`는 HTTP 503 JSON을 반환한다. 지도/검색/즐겨찾기/GPS/날씨 등은 계속 작동한다.
서버는 브라우저용 파일만 명시적으로 제공하며 `.env`, 서버 코드, 테스트, `.git`, 의존성은 제공하지 않는다.
기존 단순 정적 서버나 GitHub Pages/Live Server만으로는 프록시가 실행되지 않는다.
Public GitHub에는 코드를 공개할 수 있지만 물때를 배포하려면 Node 서버 실행 환경이 필요하다.

## 검색 및 필터

`spot-filters.js`에서 검색, 필터 옵션 생성, AND 조합, 결과 목록 및 초기화를 관리한다.
`script.js`는 기존 마커/팝업을 재사용해 표시 여부와 지도 이동을 처리한다.
별도 프레임워크나 검색 API, 데이터베이스는 사용하지 않는다.

- 검색 대상: 이름, 주소, 지역, 개인 메모, 공개 별칭, 공개/제보 어종, 낚시 방법.
- 부분 검색을 지원하며 공백으로 나눈 여러 단어는 모두 일치해야 한다. 영문 대소문자와 호환 문자는 정규화한다.
- 69개 전체 기록을 검색한다. 좌표 미확인 25곳은 목록에 `위치 확인 필요`로 남기고 선택을 막는다. 추정 좌표나 마커를 만들지 않는다.
- 지도 표시 개수는 조건에 맞는 좌표 확인 항목 수이며, 현재 화면 범위 밖의 마커도 포함한다. 전체는 44개이다.
- 검색 결과를 클릭/터치/Enter로 선택하면 기존 MapLibre `flyTo`로 해당 좌표로 이동하고 최소 zoom 13으로 확대한 뒤 동일한 팝업을 연다.
- 검색 결과 목록은 높이가 제한된 내부 스크롤 영역이다. 일반 문서 흐름에 배치해 필터, 지도 버튼, 마커를 덮지 않는다.
- 세 필터는 종류마다 하나씩 선택하며 검색어와 함께 AND로 적용한다. 선택하지 않은 `전체`는 조건에서 제외한다.
- 필터 변경 시 기존 마커를 제거/재연결한다. 선택된 포인트가 제외되면 팝업도 닫고, 기존 파란색/코럴 색상은 유지한다.
- `초기화`는 검색어, 세 필터, 즐겨찾기 필터, 결과 목록과 팝업을 지우고 44개 마커 및 현재 화면 크기에 맞는 제주 전체 보기를 복원한다. 저장된 즐겨찾기는 삭제하지 않는다.
- 키보드 Tab/방향키로 검색 결과를 이동하고 Enter로 선택할 수 있다. Escape는 결과 목록 또는 팝업을 닫는다.
- 지도 로딩 중에는 검색/필터를 비활성화하고, 지도 로딩 실패 시 오류 상태를 표시한다.

개인 메모의 어종/방법은 필터 판정에만 참고한다. `species`, `methods`, `reportedSpecies`,
`userNote`나 좌표를 변경하지 않으며, 기존 팝업의 공개/제보/메모 구분도 유지한다.
구체적인 어종만 인식하므로 `4대 돔`을 특정 어종으로 확장하지 않는다.
`서프루어`를 일반 `루어`, `넙치농어`를 `농어`, `무늬오징어`를 일반 `오징어`로 자동 분류하지 않는다.

### 현재 필터 목록

메뉴는 실제 배열/제보 어종과 개인 메모의 명시적 용어로 자동 생성한다. 가나다순이며 각 메뉴에 `전체`가 있다.

| 필터 | 현재 값 |
| --- | --- |
| 어종 (30개) | 갈치, 감성돔, 고등어, 광어, 넙치농어, 노래미, 농어, 다금바리, 독가시치, 돌돔, 무늬오징어, 방어, 벤자리, 벵에돔, 보리멸, 볼락, 부시리, 붕장어, 삼치, 숭어, 오징어, 우럭, 자리돔, 잿방어, 전갱이, 점다랑어, 참돔, 학꽁치, 한치, 혹돔 |
| 낚시 방법 (9개) | 구멍치기, 루어, 릴찌, 민장대, 서프루어, 에깅, 원투, 지깅, 찌낚시 |
| 포인트 유형 (3개) | 일반 낚시 포인트, 개인 저장 포인트, 접근 포인트 |

유형은 출처(`개인 즐겨찾기`)가 아니라 실제 `kind`를 따른다. `fishing-spot`은 일반,
`personal-spot`과 `landmark`는 개인 저장, `access-point`는 접근 포인트다.
따라서 개인 원본 목록에서 온 항구라도 `fishing-spot`이면 일반 유형에 속한다.
현재 표시 항목은 일반 39곳, 개인 저장 3곳, 접근 2곳이며 코럴 마커는 개인 저장/접근 5곳이다.

UI의 검색/초기화 아이콘은 Lucide 0.577.0의 정적 SVG로 프로젝트 내부에 저장했다.
런타임 아이콘 CDN은 추가하지 않았고 라이선스는 `assets/LUCIDE-LICENSE.txt`에 포함했다.

## 즐겨찾기

`favorites.js`는 `createFavoriteStore()`로 저장 목록과 변경 알림을 관리한다.
서버 저장이나 데이터베이스 없이 브라우저 localStorage의 `jejuFishingFavorites` 키에
`[3,8,67]`처럼 고유한 숫자 ID 배열만 JSON으로 저장한다. 포인트 전체 데이터는 저장하지 않는다.
69개 포인트의 ID는 모두 고유한 정수이며 기존 데이터/좌표는 수정하지 않았다.

- 팝업 하단의 하트 버튼은 `즐겨찾기`와 `즐겨찾기됨`을 오가며 개별 추가/해제한다.
- 같은 ID는 중복 저장하지 않는다. 팝업을 닫거나 검색으로 다시 열어도 현재 상태를 표시한다.
- 지도 위 `즐겨찾기 N` 체크박스는 즐겨찾기만 표시하며 검색/어종/방법/유형과 AND로 결합한다.
- 숫자는 전체 저장 목록의 개수이며, 지도 표시 개수는 현재 조건과 좌표 확인 기준을 만족하는 마커 수다.
- 마커의 파란색/코럴색은 그대로 유지하고 작은 하트 배지와 `fishing-marker-favorite` 클래스만 추가한다.
- 하트 아이콘은 기존 Lucide 0.577.0 라이선스의 `heart.svg`와 채움 변형 `heart-filled.svg`다.
- 즐겨찾기가 0개인 상태에서 체크하면 마커를 숨기고 `아직 즐겨찾기한 포인트가 없습니다.`를 표시한다.
- 초기화는 즐겨찾기 필터만 끄며 localStorage 목록은 유지한다. 전체 삭제 버튼은 추가하지 않았다.
- JSON 파싱 실패나 잘못된 값은 빈 배열로 복구하고, 중복/미존재 ID는 정리한다. 다른 localStorage 키는 건드리지 않는다.
- 현재 데이터에 존재하지만 좌표 미확인인 저장 ID는 보존하며 마커는 만들지 않는다.
- 저장소 접근/용량 오류가 있으면 앱은 계속 작동하고 현재 페이지의 임시 즐겨찾기를 사용한다. 새로고침 시 변경 내용이 사라질 수 있음을 표시한다.
- 같은 주소의 다른 탭에서 변경한 저장 목록은 `storage` 이벤트로 버튼·마커·개수·필터에 반영한다.
- 모바일 버튼의 높이는 44px 이상이며 팝업 본문은 기존 내부 스크롤로 유지한다. 본문은 최소 64px을 확보하고 버튼은 스크롤 바깥에 둔다.

저장은 브라우저와 origin(프로토콜·호스트·포트)별로 구분된다.
`127.0.0.1:8080`, `127.0.0.1:8081`, `localhost:8080`의 목록은 서로 공유되지 않으므로
확인할 때 동일한 주소를 사용한다. 일반 브라우저에서는 새로고침/종료 후에도 유지되지만,
시크릿 모드 종료나 사이트 데이터 삭제 시에는 목록이 사라질 수 있다.
참고: [MDN localStorage](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage).

## 내 위치 및 가까운 포인트

`location.js`에서 위치 요청, 페이지 메모리 상태, 거리 표시와 가까운 목록을 관리한다.
페이지 진입/새로고침에는 위치를 조회하지 않는다. `내 위치` 버튼을 클릭할 때만
브라우저 `navigator.geolocation.getCurrentPosition()`을 호출한다.

- 조회 설정은 `enableHighAccuracy: true`, `timeout: 15000`, `maximumAge: 0`이다. 지속 추적은 하지 않는다.
- 현재 위치는 하나의 파란 원/흰 테두리/정적인 반투명 링 마커로 표시하고 zoom 11로 이동한다.
- 브라우저가 제공한 정확도를 안내한다. 100m 초과 오차에는 `오차가 클 수 있습니다.`를 덧붙이며 정확한 GPS 위치라고 단정하지 않는다.
- 거리는 기존 `haversineDistanceMeters()`를 재사용한 직선거리다. 1km 미만은 m, 그 이상은 소수점 한 자리 km로 표시한다. 이동 경로나 도보거리가 아니다.
- 현재 검색/어종/방법/유형/즐겨찾기 조건과 지도 마커 표시 기준을 만족하는 항목만 실제 거리순으로 정렬해 최대 5곳을 보여준다. 개인 기준점/접근 포인트도 현재 유형 조건에 따라 포함하며 기존 팝업의 구분을 유지한다.
- 좌표 미확인 항목은 가까운 목록/거리에서 제외한다. 해당 검색 결과는 기존대로 선택 불가 상태와 `위치 확인 필요`를 표시한다.
- 목록 선택은 기존 `focusSpot()`으로 이동하고 같은 팝업을 연다. 위치 확인 후에는 기존 팝업과 검색 결과에도 직선거리가 표시된다.
- 가까운 목록은 데스크톱에서 지도 왼쪽 작은 패널, 모바일/태블릿에서는 지도 아래 접을 수 있는 패널이다. 제목을 클릭하거나 키보드로 펼침/접기를 바꾼다.
- `제주 전체`는 기존 반응형 제주 중심/zoom으로 돌아오며 검색/필터/즐겨찾기 및 위치 마커/거리 정보는 유지한다. 기존 `초기화`도 위치 정보를 지우지 않는다.
- 권한 거부, 시간 초과, 위치 조회 실패, 미지원 브라우저, 비보안 HTTP 환경에는 한국어 상태 안내를 표시한다. 재조회 실패 시 이전 위치는 보존하고 기존 지도/검색/즐겨찾기를 계속 사용할 수 있다.
- 서울 등 제주 밖의 위치도 막지 않으며 실제 직선거리를 계산한다.
- 좌표/정확도는 현재 페이지 메모리에만 보관한다. localStorage, 포인트 데이터, 파일, 앱 서버에 저장하거나 별도 위치 API로 전송하지 않는다. 새로고침/페이지 종료 시 사라진다. 지도 이동에 필요한 기존 OpenFreeMap 타일 요청은 계속 발생하므로 지도 제공자는 조회한 지도 영역을 알 수 있다.

### 실행 환경

Geolocation은 보안 컨텍스트와 사용자 허용이 필요하다.
개발 시 `node serve.cjs`의 `http://127.0.0.1:8080` 또는 VS Code Live Server의 localhost 주소를 사용한다.
배포 및 휴대폰의 다른 PC 접속은 HTTPS를 사용한다. 휴대폰에서 PC의 일반 HTTP LAN IP로
접속하는 것은 localhost가 아니므로 위치 조회가 차단될 수 있다.
`file://` 직접 열기는 브라우저별 동작/권한 차이가 있어 권장하지 않는다.
거부 상태에서는 주소창의 사이트 권한과 OS 위치 설정을 확인하고 `내 위치`로 재시도한다.
기존 서버가 실행 중이면 새 파일 제공 목록을 반영하도록 재시작한다.

참고: [MDN getCurrentPosition](https://developer.mozilla.org/en-US/docs/Web/API/Geolocation/getCurrentPosition),
[보안 컨텍스트](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts),
[위치 정확도](https://developer.mozilla.org/en-US/docs/Web/API/GeolocationCoordinates/accuracy).
위치/제주 전체 아이콘도 기존 Lucide 0.577.0 라이선스의 정적 SVG이며 새 런타임 의존성은 없다.

## 포인트별 날씨 및 해상 상태

`weather.js`에서 브라우저 `fetch`로 Open-Meteo 공식 공개 API를 직접 호출한다.
날씨에는 API 키, 회원가입, 프레임워크, 데이터베이스가 필요하지 않다.
별도의 공식 물때 프록시와 달리 날씨 요청은 기존대로 브라우저에서 직접 처리한다.

- 페이지 로딩, 마커 생성, 검색/필터 변경, GPS 조회에는 날씨 API를 호출하지 않는다. 실제 포인트 팝업이 열릴 때만 그 기록의 확인된 위도/경도를 요청한다.
- 요청은 `fishing-spots.js`의 좌표를 그대로 사용한다. 예: 서부두 ID 43 `(33.5227588, 126.5301222)`, 현사포구 ID 67 `(33.49753, 126.449588)`. 사용자 GPS를 날씨 API에 전달하지 않는다.
- 육상: `https://api.open-meteo.com/v1/forecast`의 `models=kma_seamless`를 우선 사용한다. KMA 데이터가 전부 비어 있거나 요청이 실패하면 같은 공식 Forecast API의 자동 모델 선택으로 한 번만 대체한다. HTTP 429는 추가 대체 요청 없이 오류로 표시한다. 대체 여부는 팝업에 명시하며 서로 다른 모델의 항목을 임의로 혼합하지 않는다.
- 해상: `https://marine-api.open-meteo.com/v1/marine`, `cell_selection=sea`, `length_unit=metric`. 요청 좌표와 실제 예보 격자 중심은 다를 수 있으며 방파제 안쪽의 실측 수치가 아니다.

| API | current 요청 변수 | hourly 요청 변수 |
| --- | --- | --- |
| Forecast | `temperature_2m`, `apparent_temperature`, `wind_speed_10m`, `wind_direction_10m`, `wind_gusts_10m`, `precipitation`, `weather_code` | `wind_speed_10m` |
| Marine | `wave_height`, `wave_direction`, `wave_period`, `sea_surface_temperature` | `wave_height` |

육상 단위는 요청 옵션 `wind_speed_unit=ms`, `temperature_unit=celsius`, `precipitation_unit=mm`로 지정한다.
응답 단위를 검사하며 바람이 km/h로 오면 3.6으로 나눠 m/s로 변환한다. 숫자가 아닌 값,
누락값, 알 수 없는 단위는 `정보 없음`으로 표시한다. 0은 누락값으로 취급하지 않는다.
풍향/파향은 공통 8방위 변환과 각도를 사용한다. 파향은 파도가 **오는 방향**이다.
강수량은 API의 current 구간값이며 하루 총강수량이라고 표시하지 않는다.

두 API에 `timezone=Asia/Seoul`, `timeformat=unixtime`, `forecast_hours=8`을 요청한다.
UNIX 시간에 UTC 오프셋을 다시 더하지 않고 `Intl.DateTimeFormat`의 Asia/Seoul로 표시한다.
현재 시각의 정시를 기준으로 +2/+4/+6시간 3행을 만들며 시간값으로 두 응답을 연결한다.
한쪽 API가 실패하면 가능한 파고 또는 풍속만 표시하고 빠진 열은 `정보 없음`으로 둔다.
현재 모델 기준 시각과 조회 시각을 각각 표시하며 예보 시간 제목의 tooltip에도 한국 날짜/시간을 둔다.

`createSpotWeatherService()`는 API 종류와 정확한 좌표를 키로 성공 응답을 10분간 메모리에 저장한다.
진행 중인 같은 요청은 하나의 Promise를 공유하고, 만료 후 팝업을 다시 열면 갱신한다.
KMA 대체 결과도 캐시하며 실패한 요청은 다음 열기에서 다시 시도할 수 있다.
각 HTTP 요청의 시간 제한은 12초이고, KMA 대체까지 진행하면 육상 조회는 최대 약 24초가 걸릴 수 있다.
캐시는 새로고침 시 사라지며 localStorage나 원본 포인트/화장실 데이터에 저장하지 않는다.

로딩/응답 갱신은 날씨 영역만 바꾼다. 팝업 이름, 어종, 메모, 화장실, 즐겨찾기를 재생성하지 않는다.
실패한 API의 영역에만 한국어 오류를 표시하며 정상인 다른 API와 기존 기능은 계속 사용할 수 있다.
현재 해상 변수들이 비어 있으면 `현재 이 위치의 해상 정보가 제공되지 않습니다.`를 표시한다.
팝업 내부 스크롤 높이는 기존 지도 높이/헤더/버튼 및 실제 전체 높이를 고려하며 긴 이름과 GPS 거리도 수용한다.

현재 값은 최신 **모델 기반 예보값**이지 현장 관측 실황이나 공식 안전 판단이 아니다.
특히 연안/방파제의 실제 파고와 다를 수 있다. 참고용 안내 및 기상특보·해양경찰/현장 통제 확인 문구를 표시한다.
출조 추천/안전 점수, 특보 자동 판단, `sea_level_height_msl`은 구현하거나 요청하지 않았다.
만조/간조는 Open-Meteo 값으로 만들지 않으며 아래 별도 KHOA 조석예보 영역에서만 표시한다.

무료 API는 비상업용 조건과 호출 제한이 있다. 현재 약관 기준 분당 600회, 시간당 5,000회,
하루 10,000회 미만이며 광고/유료 서비스 등 상업 배포 시 무료 조건을 다시 확인해야 한다.
팝업에 Open-Meteo, KMA 및 DWD 등 해상 자료 출처를 표시한다.
문서: [Forecast](https://open-meteo.com/en/docs), [KMA](https://open-meteo.com/en/docs/kma-api),
[Marine](https://open-meteo.com/en/docs/marine-weather-api), [이용 약관](https://open-meteo.com/en/terms).

2026-10-02 확인한 KMA 공식 API 문서는 UM에서 KIM 모델로 전환하는 동안 Open-Meteo의
KMA 데이터 갱신이 중단되었다고 안내한다. 개발 검증에서도 서부두/현사포구의 KMA current 값이
비어 있어 자동 선택 예보로 대체됐으며,
브라우저에서 기온/풍속과 Marine 파고/주기/표층 수온을 정상 수신했다. 앞으로 데이터 제공 상태는 바뀔 수 있다.

## 공식 조석예보

공식 API 이름은 **해양수산부 국립해양조사원_조석예보(고, 저조)**이다.
[공공데이터포털의 활용명세/Swagger](https://www.data.go.kr/data/15156018/openapi.do)와
[KHOA 공식 API 조회 화면](https://khoa.go.kr/oceandata/openapi/odmi/odmiApiViewData.do?apiId=SV_AP_04_006)의
지점 목록 및 응답을 2026-10-02 확인했다. 비공식 물때 사이트 크롤링이나 지점 코드 추정은 하지 않는다.

- 고정 upstream endpoint: `https://apis.data.go.kr/1192136/tideFcstHghLw/GetTideFcstHghLwApiService`
- GET 파라미터: `serviceKey` (서버에서만 추가), `obsCode`, `reqDate=yyyyMMdd`, `type=json`, `pageNo=1`, `numOfRows=300`.
- frontend는 같은 서버의 `/api/tides?station=DT_0004&date=20261002`처럼 지점/날짜만 전달한다. 좌표나 GPS, 외부 URL, 키는 보내지 않는다.
- 프록시는 아래 4개 코드와 한국 날짜 기준 오늘/내일만 허용한다. 중복/추가 query나 잘못된 날짜를 거부하며 외부 리다이렉트도 따라가지 않는다.

| 기준지점 | 공식 코드 | 위도 | 경도 |
| --- | --- | ---: | ---: |
| 제주 | `DT_0004` | 33.52750 | 126.54305 |
| 성산포 | `DT_0022` | 33.47472 | 126.92777 |
| 서귀포 | `DT_0010` | 33.24000 | 126.56166 |
| 모슬포 | `DT_0023` | 33.21444 | 126.25111 |

코드/좌표는 `tide-utils.js`에서 공개 메타데이터로 관리한다. `tides.js`는 기존
`haversineDistanceMeters()`로 낚시 포인트에서 가장 가까운 기준지점을 선택한다.
지역 이름으로 하드코딩하지 않으므로 모든 서부 포인트가 반드시 모슬포에 연결되는 것은 아니다.
예: 서부두는 제주, 온평리포구는 성산포, 서귀포항은 서귀포, 신도포구는 모슬포에 연결된다.
포인트 자체의 실측 정보처럼 표시하지 않고 반드시 `기준지점 · 이름`을 표시한다.

공식 JSON의 `header.resultCode === "00"`와 `body.items.item`을 읽는다.
`obsvtrNm` (예보지점명), `lat`/`lot` (위도/경도), `predcDt` (예측일시),
`predcTdlvVl` (**cm**), `extrSe`를 사용한다. 공식 극치 구분은
**1: 오전 고조, 2: 오전 저조, 3: 오후 고조, 4: 오후 저조**이며 1/3은 만조, 2/4는 간조로 표시한다.
명세와 공식 조회 응답의 날짜 문자열은 한국 시간으로 파싱해 epoch 밀리초로 변환한다.
시간순으로 정렬하고 단위를 cm로 유지한다. 0과 음수 조위도 유효한 실제 값이면 그대로 표시한다.
잘못된 일시/지점/단위/숫자, 누락값이나 불완전 페이지는 추정해서 채우지 않고 오류로 처리한다.

물때 영역은 기존 팝업의 날씨 아래 별도로 추가하며 해상 파고/수온과 섞지 않는다.
기존 팝업/즐겨찾기를 재생성하지 않으며 내부 스크롤과 44px 이상 오늘/내일 버튼을 유지한다.
기본은 오늘, 내일 탭 선택 시에만 내일을 추가 요청한다. 단 오늘 마지막 극치가 지났거나
오늘 예보가 비어 다음 물때를 찾을 수 없으면 다음 물때 표시를 위해 내일도 한 번 요청한다.
오늘 데이터 요청 실패만으로 내일의 이벤트를 현재의 다음 물때라고 단정하지 않는다.
다음 물때는 현재 timestamp 이상인 가장 빠른 이벤트이며, 남은 시간은 분 단위로 올림한다.
팝업이 열린 동안 1분마다 남은 시간/한국 날짜를 다시 계산하고 닫으면 타이머를 해제한다.
자정에는 새 오늘/내일을 사용하며 미리 받은 날짜는 재사용한다.

브라우저와 서버 모두 `stationCode:date`로 성공 응답과 진행 중인 요청을 공유한다.
같은 지점/날짜의 데이터는 해당 한국 날짜가 끝날 때까지 재사용한다. 내일 미리 받은 값도
그 날짜가 오늘이 됐을 때 유지한다. 지난 날짜 캐시는 제거한다.
브라우저 새로고침/서버 재시작 시 각각의 메모리 캐시는 사라지고 파일/DB/localStorage에는 저장하지 않는다.
서버 HTTP 시간 제한은 12초, 브라우저는 15초다. 서버 실패는 30초 동안 재사용해 반복 실패 호출을 줄인다.
키 미설정, 인증/통신 오류, 시간 초과, XML 오류 응답, 잘못된 JSON에는 물때 영역만 한국어 오류를 표시한다.
upstream 오류/URL/키는 출력하거나 클라이언트에 보내지 않는다. 재조회는 잠시 후 팝업을 다시 연다.

출처 링크와 `국립해양조사원 조석예보 기준이며, 실제 현장 조위와 차이가 있을 수 있습니다.`를 표시한다.
기존 기상특보·해양경찰·현장 통제 확인 문구도 유지한다. `몇 물`, 조금/무시, 추천 시간,
낚시 성과/안전 점수 등은 계산하지 않는다.

공식 공개 조회 응답은 `tests/fixtures/khoa-tides.json`에 **파서 테스트 자료로만** 보관한다.
실행 앱에서는 테스트 자료/샘플 물때를 실제 예보 대신 보여주지 않는다.
2026-10-02 제출 전 점검에서 로컬 `.env`의 키로 제주/성산포/서귀포/모슬포의 오늘·내일
인증된 endpoint 응답(HTTP 200, 날짜별 이벤트 4개)을 확인했다. 초기 일부 요청은 연결 오류가
발생했으나 재시도 후 성공했다. 키 값과 원본 요청 URL은 기록하지 않았다.
실제 휴대폰/제출 환경에서 오늘·내일 전환과 기준지점, 조위/시간의 공식 조회 화면 대조는 별도로 확인해야 한다.

- `species`, `methods`: 해당 장소의 공개 낚시 자료에서 확인한 목록 또는 주요 항목.
- `reportedSpecies`: 이번에 사용자가 직접 제보한 추가 어종. 공개 자료의 어종과 분리하며 현재 조황이나 상시 출현을 보장하지 않는다.
- `source`: 개인 기록은 `개인 즐겨찾기`, 새 공개 기록은 `바다타임`.
- `externalSources`: 실제 참고한 공개 자료. 이름만 확인한 출처가 좌표 검증 출처가 되는 것은 아니다.
- `coordinateSource`, `coordinateScope`: 좌표의 근거와 범위.
- `kind`: 일반 낚시 장소와 개인 기준점/접근 지점의 구분.
- `locationNote`: 기준점과 실제 해안 낚시 위치가 다르다는 안내.
- `fishingInfoSource`: 어종과 방법의 근거. 관광지 좌표 출처와 별개로 관리한다.
- `additionalFishingInfoSources`: 추가 어종과 해당 어종을 소개하는 공개 출처. 기존 출처를 덮어쓰지 않는다.
- `verificationNote`: 확인 범위, 불확실성 또는 마커 제외 이유.

좌표는 공개 자료의 방파제/포구/해변 **대표 위치**이며, 사용자가 저장한 개인 핀의
정밀 위치를 복원한 것이 아니다. 출입 가능 여부, 낚시 허용, 현재 조황 및 안전을
보장하지 않는다. 공개 자료에 없는 어종과 방법은 빈 배열로 남겼다.
개인 메모만 있는 해수욕장, 용수포구, 용담포구, 북촌포구 등의 어종을 추정하지 않았다.
미확인 동귀방파제의 어종과 방법은 피싱맵에서 확인했지만 좌표가 없어 마커는 만들지 않는다.

| 연결됨 / 확인된 정보 없음 | 표시 포인트 44곳 중 22곳 / 22곳 |

주소가 `제주특별자치도`로 시작하고 제주 좌표 범위 안의 유효한 위도/경도를 가진
항목만 저장했다. 좌표/주소를 확인할 수 없는 기록은 제외했다.
폐쇄 보도가 있는 기존 현사마을 화장실 `PT0363`도 제외했다.
근거: [한라일보 현사포구 화장실 보도](https://www.ihalla.com/article.php?aid=1768097712780944044).
개방시간은 원자료를 유지하며 빈 값이나 `불규칙`은 `정보 없음`으로 처리했다.
`연중무휴`를 24시간 개방으로 바꾸지 않는다. 개방화장실에는 민간 개방 시설도 포함된다.

서귀포시 전체 자료를 확보한 것은 아니며 이번 요청 주변의 공개 후보 6개만 보완했다.
POOPOO는 공공데이터 참고 기록을 제공하는 보조 출처이며 이 6개를 제주시 공식 CSV
기록이라고 표시하지 않는다. 공개 자료의 주소/좌표/시간을 대조했지만 현장 검증은 아니다.
2024년 이후의 개방시간 변경 및 기관 시설의 외부인 이용 가능 여부는 직접 확인해야 한다.
새 좌표의 포인트를 추가하면 정적 데이터의 수집 범위도 다시 검토해야 한다.
좌표가 없는 포인트 25곳은 거리 계산에서 제외한다.

팝업 아래에 이름, 약 거리(직선거리), 시간, 주소, 관리기관, 기준일 및 출처를 표시한다.
수정된 현사포구에는 약 410m의 이호테우해변(상황실1층)(`상시`)이 연결된다.
일치하는 자료가 없으면 정확히 `500m 이내 확인된 공중화장실 정보 없음`을 표시한다.
이는 실제 화장실이 없다는 뜻이 아니다. 직선거리는 도보거리와 다르며,
원자료 이후의 폐쇄/시간 변경과 현재 이용 가능 여부는 현장에서 확인해야 한다.
화장실용 지도 마커나 토글은 추가하지 않았다.

## 공개 자료를 개인 항목에 연결한 명칭

### 제주항 부두 및 갈치 보완

서부두(ID 43)와 동부두(ID 45)는 삭제됐던 것이 아니라 어느 항구인지 미확인이라
마커를 보류한 항목이었다. 이번 사용자 요청으로 제주항임을 확인하여 기존 ID와
이름/메모를 유지하고 각각 육지 연결 서부두 방파제 끝과 동방파제 등대 기준점을 표시한다.
[OpenStreetMap 서부두 방파제](https://www.openstreetmap.org/way/452011513)의 끝점과
동방파제 등대를 개발 중 일회성으로 조회했고,
[과거 공식 검역구역 자료의 등대 좌표](https://www.law.go.kr/flDownload.do?bylClsCd=110201&flSeq=102421597&gubun=)와
대조했다. 이 과거 자료로 현재 출입 규정을 판단하지 않는다.
기존 제주항방파제 빨간등대(ID 52)는 바다 쪽 긴방파제의 별도 지점으로 좌표/어종을 바꾸지 않았다.

[피싱맵 제주항·서부두·동부두](https://fishingmap.co.kr/mobile/m_map_view.php?no=1020&wher=16)의
항만 주요 어종 목록으로 두 부두의 공개 어종을 보완했다. 부시리는 이 공개 목록에 포함된다.
갈치·점다랑어·잿방어는 사용자의 이번 제보를 `reportedSpecies`로 저장하며,
팝업의 `사용자 제보 어종`에 표시한다. 공개 자료와 중복되는 부시리는 한 번만 보여준다.
`모든 어종이 항상 잡힌다`고 표시하지 않으며 자료의 오래된 공사/진입 안내도 재사용하지 않는다.

애월항(ID 23)에는 [2025년 애월항 방파제 야간낚시 가이드](https://pigkim4.tistory.com/14)에서
대상어로 소개한 갈치를 추가하고 해당 출처를 별도 연결했다. 이는 공개 가이드의 대상어
안내이지 실제 현장 조사나 실시간 조황 검증은 아니다. 기존 바다타임 어종/방법과 출처는
유지한다. 갈치배 출항 안내나 먼바다 선상 조과만으로 다른 방파제의 어종을 추가하지 않았다.
나머지 66개 기록, 원래 메모, 화장실 147개, 지도 라이브러리/카메라/디자인은 그대로다.
동부두는 기존 500m 규칙에 따라 국제여객터미널 화장실(약 400m)과 연결되고,
서부두는 저장 자료 중 500m 이내 확인된 공중화장실 정보가 없다.
